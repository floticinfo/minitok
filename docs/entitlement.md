# minitok Entitlement — User Guide

This guide covers purchasing, activating, and managing your minitok license.

## Purchasing a license

1. Open the license management page in your browser: `http://localhost:3000` (or your deployment's public URL).
2. Enter the license key you received at purchase and sign in.
3. The page shows the devices currently bound to your key, the plan, and the expiry date.

License keys are issued after checkout. Each key activates a plan (`level1`, `trial`) with a device limit (`maxDevices`) and an expiry date.

## Activating minitok

### CLI

```sh
minitok activate <your-license-key>
```

The CLI calls the entitlement server (`POST /api/entitlement/activate`), receives a short-lived session token (JWT, 24 h), and stores it locally in `~/.minitok/entitlement/session.json`. After activation, gated commands (`minitok run`, MCP tool calls, the extension's Run button) work without further interaction.

To use a key stored in an environment variable instead of typing it:

```sh
minitok activate --key-env MINITOK_ACTIVATION_KEY
```

### VS Code extension

Use the **minitok: Activate License** command (Command Palette → `minitok.activate`) and paste the key. The extension performs the same server exchange and stores the session in VS Code SecretStorage (`minitok.secret.entitlement`), so the sidebar shows your plan and expiry even offline.

### What counts as a device

Each activation is bound to an installation id generated by the server. Re-activating with the same key on the same installation reuses the slot; activating on a new machine consumes another slot up to the plan's `maxDevices`.

## Offline use

- **CLI**: after a successful online validation, the signed local entitlement keeps working for up to 7 days if the server is unreachable (offline grace). The grace window is monotonic — rolling the system clock back is detected and blocked.
- **Extension**: the cached session's JWT `exp` claim authorizes offline work until the token expires.

## Managing devices

On the management page (`http://localhost:3000`):

- **List devices**: sign in with your license key to see every bound installation, its activation time, last-seen time, and status (active/released).
- **Release a device**: click *Release* next to an installation to free the slot. Releasing is permanent for that binding; the released device can no longer use the key.

Releasing requires your key — the page exchanges it for a 30-minute admin session and never stores the raw key in the browser.

## Troubleshooting

| Symptom | Meaning | Fix |
| --- | --- | --- |
| `minitok requires an active entitlement...` (MISSING) | No local entitlement found. | Run `minitok activate <key>`. |
| `Your minitok entitlement has expired...` (EXPIRED) | The subscription period ended. | Renew, then `minitok activate <key>` again. |
| `This entitlement was issued for a different installation...` (INSTALLATION_MISMATCH) | The local artifact belongs to another machine. | Activate on this machine with your key. |
| `The entitlement server rejected this installation...` (SERVER_REJECTED) | The key was revoked or released. | Check the management page; re-activate if the key is still valid. |
| `The entitlement server could not be reached...` (SERVER_UNREACHABLE) | Network/firewall blocks the server. | Within the 7-day grace period work continues offline; otherwise restore connectivity and run `minitok status`. |
| `System clock appears to have been set back...` (CLOCK_ROLLBACK) | Clock rollback detected. | Correct the system clock. |
| MCP: `License required` (`-32003`) at handshake | The MCP host did not present an entitlement credential. | Activate the CLI on the host machine, or set `MINITOK_ENTITLEMENT` in the host's server config. |

### Useful commands

```sh
minitok status          # show current entitlement state
minitok deactivate      # remove the local session (does not revoke server-side)
```

## Security notes

- The license key is only sent to the entitlement server over HTTP(S); it is never written to MCP host configs (`mcp.json`, VS Code/Claude settings).
- Local artifacts in `~/.minitok/entitlement/` are written with owner-only permissions (`0600`) where the platform supports it.
